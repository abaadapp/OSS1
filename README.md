# Event Plus — نظام إدارة الشركة

نظامٌ إداريّ **داخليّ** لشركة Event Plus: العملاء والمشتريات والمخزون والمالية
والموظفون، بدفترِ أستاذٍ مزدوج القيد تحته.

> **المشروع قيد التحويل.** أساسُه نظامُ إدارةِ متاجرَ بالتجزئة، ويُحوَّل تدريجيًّا
> إلى نظام عمليّاتٍ لشركة خدمات. ما في هذا الملفّ هو ما يعمل **اليوم** — لا ما
> يُنوى. انظر [EVENTPLUS_SYSTEM_STATE.md](EVENTPLUS_SYSTEM_STATE.md) لحالة النظام
> بالتفصيل.

## المتطلّبات

PHP 8.4 · Composer 2 · Node 22+ · SQLite محلّيًّا (PostgreSQL على الإنتاج)

## التشغيل المحلّي

```bash
composer setup                 # تثبيت + مفتاح + هجرات + بناء
php artisan migrate --seed     # شركةٌ واحدة بمالكها وافتراضياتها
composer dev                   # الخادم والطابور والسجلّات وVite معًا
```

ثمّ افتح <http://127.0.0.1:8000>. الصفحةُ الرئيسيّة هي صفحةُ الدخول.

حسابُ الدخول الأوّل يُضبط في `.env` (`SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD`)
— غيّرهما قبل أيّ نشر. انظر [SEEDING.md](SEEDING.md).

## المكدّس

| الطبقة | ما فيها |
|---|---|
| الخلفية | Laravel 13 · PHP 8.4 |
| الواجهة | Inertia 3 + React 19 + TypeScript + Tailwind 4 |
| البناء | Vite 8 (`laravel-vite-plugin`) |
| القاعدة | SQLite محلّيًّا · PostgreSQL على الإنتاج |
| الاختبار | PHPUnit (خلفية) · Vitest (واجهة) |

## البنية

| المسار | ما فيه |
|---|---|
| `routes/web.php` | كلُّ المسارات — مجموعةٌ واحدة تحت `auth → tenant → business → panel → ability` |
| `app/Http/Controllers/` | متحكّمات رقيقة: تتحقّق، تستدعي طبقة الدعم، تُعيد Inertia |
| `app/Support/` | حيث يعيش المنطق: الدفتر والفواتير والصلاحيات والمستندات |
| `app/Models/` | Eloquent — كلُّ جداول المستأجر تحت `business_id` |
| `resources/js/` | واجهة Inertia + React |
| `resources/views/documents/` | قوالبُ الأوراق (فاتورة، سند تسليم، أمر شراء، سند استلام) |
| `database/migrations/` | الهجرات، مسمّاةً بجُمَلٍ تصف السلوك لا أسماءَ جداول |
| `tests/` | PHPUnit في `tests/Feature` و`tests/Unit`، وVitest في `tests/js` |
| `design-system/` | رموز التصميم |

## مبدآن يحكمان الكود

**١) `business_id` في كلّ جدولٍ للمستأجر.** الحارسُ عند الباب (`RequiresBusiness`)
لا في كلّ شاشة. أُبقي عمدًا: يصلح لاحقًا لفصل أكثر من شركةٍ داخل النظام نفسه.

**٢) بابٌ واحد لكلّ كتابةٍ خطرة.** لا يدخل الدفترَ قيدٌ إلّا من `Ledger::post`،
ولا يُعدَّل بندُ فاتورةٍ صدرت إلّا من `OrderCorrection`، ولا تتحرّك كميّةٌ إلّا
من `StockLedger`.

## أوامر

```bash
composer test      # اختبارات PHP
npm test           # اختبارات الواجهة (vitest)
npx tsc --noEmit   # فحص الأنواع
php artisan eventplus:preflight   # فحص جاهزية النشر
```

## اصطلاحات المستودع

- تعليقات الكود ورسائل الالتزام بالعربية.
- أسماء ملفات الهجرات والاختبارات جُمَلٌ تصف السلوك المقصود، لا أسماءَ جداول.
- كلُّ نصٍّ عربيٍّ يراه المستخدم يمرّ بـ`__()` أو `t()`، وله مقابلٌ في `lang/en.json`
  — يحرسه `TranslationCoverageTest`.

## قبل التعديل

افحص الكود الحالي قبل تغييره. واقعُ المستودع أولى من أيّ افتراضٍ سابق.
