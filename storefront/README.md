# افنت بلس — عارض مواقع التجّار

يحوّل **مستند الموقع** الذي يبنيه افنت بلس إلى موقعٍ حقيقيّ يفتحه زبون التاجر
على نطاقه هو.

افنت بلس تبني الموقع ولا تعرضه. هذا التطبيق يعرضه — ويسكن `storefront/` داخل
مستودع افنت بلس، ولا يعرف عن افنت بلس شيئًا سوى طلبٍ واحد:

```
GET {EVENTPLUS_API_URL}/site/{host}
```

ويعرف هذا الطلبُ نطاقَ التاجر الذي يملكه (`site_domain`) والنطاقَ الفرعيّ
الذي حجزه في افنت بلس (`اسمه.eventplusapp.om`) — كلاهما يصل إلى موقعه.

## كيف يعمل

```
زائرٌ يفتح  wrood.om
        ↓
nginx  →  هذا الخادم (Node)
        ↓  الترويسة Host تُقرأ وتُنقّى   (src/lib/host.ts)
GET https://app.eventplusapp.om/site/wrood.om   (src/lib/api.ts)
        ↓  المستند: قالبٌ وصفحاتٌ وأقسامٌ ومنتجاتٌ وهويّة
src/lib/routing.ts   المسار ← الصفحة
src/lib/seo.ts       العنوان والوصف وبطاقة المشاركة
src/site/            الرسم: ترويسة + أقسام + تذييل
```

ولا قاعدة بيانات هنا، ولا نسخةَ ثانية من كتالوج المنتجات. المصدر واحد.

## البنية

| المجلّد | ما فيه |
|---|---|
| `src/app/` | مسارات Next: الصفحة الشاملة، `robots.txt`، `sitemap.xml`، الغلاف |
| `src/lib/` | حلُّ المضيف، عميل الـAPI، التوجيه، الوسوم |
| `src/components/` | حالاتٌ ليست موقعًا: ٤٠٤ وصيانةٌ وغيرُ متاح |
| **`src/site/`** | **طبقة الرسم — مشتركة، انظر أدناه** |
| `tests/` | ١٠٦ اختبارات تقرأ مستنداتٍ حقيقيّة مولَّدة من افنت بلس |

## طبقة الرسم مشتركة — لا تُعدَّل في افنت بلس

`src/site/` هي **الشيفرة نفسها** التي تُرسم بها المعاينة داخل لوحة افنت بلس.
نسخةٌ واحدة، والاتجاه واحد:

```bash
node scripts/sync-renderer.mjs      # من هنا ← إلى افنت بلس
```

يُنسخ المجلّد إلى `resources/js/Pages/Admin/Website/preview/renderer/` في جذر المستودع
وتُكتب بصمةٌ في `RENDERER_HASH` على الطرفين. ومن عدّل أحد الطرفين بلا مزامنة
يسقط اختبارُ ذلك الطرف:

- هنا: `tests/parity.test.ts`
- في افنت بلس: `tests/Feature/RendererParityTest.php`

**ولذلك شرطان على `src/site/`:**

1. **بلا تبعيّات** — React وحدها. لا `next/*` ولا `lucide-react` ولا `@/…`
   (يحرسه `RendererParityTest`).
2. **وضعان** — `mode="live"` للموقع و`mode="edit"` للمعاينة. الفرق: القسم
   الفارغ يُقال عنه في المحرّر ولا يُرسم في الموقع، والروابط تنقل في الموقع
   ولا تنقل في المعاينة.

فما يراه التاجر في معاينته هو ما يراه زبونه — لا شبيهٌ به.

## القالب بنيةٌ لا لوحةُ ألوان

الرموزُ التي يقرؤها هذا العارض نوعان، وكلاهما في `tokens` في المستند:

| النوع | أين يُحكَم | ما يفعل |
|---|---|---|
| **اللون والخطّ** | `App\Support\Website\Theme` | لونٌ أساسيّ وخلفيةٌ ونصٌّ وخطٌّ وحوافُّ وزرّ، وما يُشتقّ منها |
| **البنية** | `App\Support\Website\Layout` ← `src/site/layout.ts` | عرضُ المحتوى وكثافةُ الفراغ وسلّمُ العناوين وشكلُ الترويسة والواجهة والبطاقة والشبكة والتصنيفات والتذييل |

ولا ملفَّ رسمٍ لكلّ قالب: `Site.tsx` واحدة، و`Header.tsx` واحدة ترسم أربعة
أشكال، و`ProductCard.tsx` واحدة ترسم أربعة. فإصلاحُ عطبٍ في بطاقة المنتج
إصلاحٌ واحد يصل القوالبَ كلَّها.

**والافتراضيُّ هو رسمُ ما قبل هذه الطبقة حرفيًّا** (`LAYOUT_DEFAULTS`):
مستندٌ نُشر قبلها يصل بلا رموز بنية، فيُرسم كما رُسم يوم نُشر.

**وللقسم أن يخالف قالبه:** حقلُ `layout` في بيانات القسم قيمتُه `auto` فيتبع
القالب، أو قيمةٌ صريحة فيخالفه — انظر `variant()` في `src/site/layout.ts`.

## إضافة قسمٍ جديد

قسمٌ يُضاف في افنت بلس (`app/Support/Website/Sections.php`) يحتاج رسمًا هنا:

1. اكتب المكوّن في `src/site/blocks.tsx`.
2. أضف سطرًا في `REGISTRY`.
3. أضف قاعدة «متى يكون فارغًا» في `src/site/content.ts`.
4. إن كان له أشكالٌ تتبع القالب، اقرأها بـ`variant(section, …)` لا بحقلٍ
   مستقلّ — فيتبدّل مع القالب لمن لم يختر.
5. `node scripts/sync-renderer.mjs`.

وحتى تفعل، لا ينهار شيء: النوع المجهول يُتخطّى ويُسجَّل تحذيرٌ للمطوّر.

## التشغيل

```bash
npm install
cp .env.example .env.local        # واضبط EVENTPLUS_API_URL
npm run dev                       # http://localhost:3000

# ولاختبار نطاقٍ بعينه محلّيًّا:
curl -H 'Host: wrood.om' http://localhost:3000
```

| الأمر | ما يفعل |
|---|---|
| `npm run build` | بناء `standalone` |
| `npm run test` | اختبارات العارض وحارسُ التطابق |
| `npm run typecheck` | `tsc --noEmit` |
| `node scripts/sync-renderer.mjs` | مزامنة طبقة الرسم مع افنت بلس |

## الإعدادات

| المتغيّر | الافتراضيّ | ما هو |
|---|---|---|
| `EVENTPLUS_API_URL` | `https://app.eventplusapp.om` | عنوان افنت بلس |
| `EVENTPLUS_API_TIMEOUT_MS` | `6000` | بعدها تُعرض «غير متاح مؤقّتًا» |
| `SITE_REVALIDATE_SECONDS` | `60` | مدّة تخزين المستند |

## ما لم يُبنَ بعد — ولماذا

| | السبب |
|---|---|
| سلّة ودفع | لا Checkout في افنت بلس بعد. وزرٌّ لا يعمل أسوأ من غيابه — فالموجود اليوم «اطلب عبر واتساب»، وهو رقمٌ حقيقيّ في إعدادات التاجر |
| صفحة منتج | المستند يحمل الاسم والسعر والصورة، ولا يحمل مخزونًا ولا خياراتٍ ولا وصفًا كاملًا. وصفحةٌ تُبنى منه صفحةٌ ناقصة |
| بحثٌ في الموقع | لا مسار في عقد المستند يُسأل عن منتجٍ باسمه |
| حجوزاتٌ وخدمات | خارج نطاق محرّك افنت بلس اليوم — والسجلّ يقبلها بسطر |
| تعدّد اللغات | لغةُ الموقع تتبع إعداد النشاط في افنت بلس (`ar` أو `en`)، ولا لغتان في موقعٍ واحد |

وحين يصل أيٌّ منها: `Site` يقبل `children` فتُرسم صفحةٌ جديدة **داخل** ترويسة
المتجر وتذييله وبرموزه، بلا إعادة بناء شيء.

## حالتان معروفتان

**صفحةٌ لا وجود لها تردّ ٢٠٠ لا ٤٠٤.** `notFound()` في Next على مسارٍ
ديناميّ كهذا تُفرغ قشرةَ HTML وتترك الرسم للمتصفّح — جُرِّبت، فوصلت الصفحةُ
خاليةً من كلّ نصّ لمن لا JavaScript عنده وللزاحف. فرُسمت الصفحةُ على الخادم
داخل ترويسة المتجر، ومُنعت الفهرسة بـ`noindex` في الوسوم — وهو ما يمنع
الفهرسة فعلًا. وكذلك «لا يوجد موقع على هذا العنوان» و«غير متاح مؤقّتًا».

**صفحة الصيانة تردّ ٢٠٠** للسبب نفسه (٥٠٣ لا تُضبط من صفحةِ Next). و`noindex`
عليها.
